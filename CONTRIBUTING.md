# Contributing

Thank you for considering a contribution to MergingFormer. The project is in an
early research-code stage, so small and focused changes are easiest to review.

## Reporting a problem

Open an issue with:

- the script and command you used;
- operating system and Python version;
- PyTorch version and whether CUDA was used;
- relevant model and data dimensions;
- the complete error message or unexpected result; and
- a minimal example when it can be shared legally.

Do not upload private, identifying, or redistribution-restricted trajectory
data. Replace sensitive values with a small synthetic example.

## Proposing a change

1. Describe the problem the change addresses.
2. Keep the pull request focused on one concern.
3. Update documentation when behaviour, data fields, paths, or dependencies
   change.
4. State which scripts you ran and what you observed.
5. Clearly disclose code, data, or ideas adapted from another source and include
   its license and URL.

There is no validated automated test suite yet. Until one is added, explain the
manual checks relevant to the changed code. Do not describe unexecuted checks as
passing.

## Code and data ownership

By submitting a contribution, you confirm that you have the right to provide it
under the repository's license. Retain third-party notices and identify copied
or adapted material in the pull request.
